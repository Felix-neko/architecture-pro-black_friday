## Принципы работы с репликами

### Операции, требующие чтения из master-ноды:
- **Чтение гостевой корзины для слияния** - критично для корректности бизнес-логики
- **Проверка запасов перед созданием заказа** - требует актуальных данных для предотвращения overselling

### Операции с допустимой задержкой репликации:
- **Cart operations** - до 15 секунд (пользовательский опыт)
- **Product catalog** - до 5 минут (поисковая выдача)
- **Product details** - до 15 секунд (проверка менеджерами)
- **Stock display** - до 30 секунд (информационное отображение)
- **Order history/status** - до 15-30 секунд (пользовательские ожидания)

## Рекомендации по архитектуре

1. **Критические операции** (Cart merge, Stock validation) должны всегда выполняться на master-ноде
2. **Пользовательские операции** могут использовать read-replica с разумными SLA по задержке
3. **Информационные операции** могут использовать replica с большими допустимыми задержками
