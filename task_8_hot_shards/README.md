# Задание 8. Выявление и устранение «горячих» шардов

## Проблема

Из-за категории «Электроника» произошла перегрузка одного из шардов MongoDB, так как 70% запросов приходилось именно на эти товары.
Сейчас нужно разработать стратегию, как выявлять и устранять такие «горячие» шарды, а ещё предложить метрики мониторинга, чтобы в будущем можно было предотвращать такие ситуации.
Не забудьте учесть, что товары из популярных категорий могут создавать непропорциональную нагрузку на отдельные узлы.

## Предлагаемое решение

### На ближайшее время
В качестве первой помощи -- нужно смотреть следующие метрики.

На нодах (если это kubernetes-кластер, смотрим через Lens):
- загрузка CPU;
- потребление памяти;
- нагрузка на диск 
- сетевой трафик.

Для каждой коллекции:
- количество чанков по шардам;
- количество документов по шардам;
- объём данных по шардам;
- количество текущих операций по шардам.

```mongodb
> db.coll_name.getShardDistribution() // количество документов и объём данных по шардам, количество чанков для шардов

> db.adminCommand("currentOp") // текущие операции
```

### На ближайшую перспективу
* Разработать реалистичный набор нагрузочных тестов на базе логов обращений к веб-серверу во время прошлой Чёрной Пятницы (скорее всего, они сохранились).
* Включить Prometheus-метрики для MongoDB (helm chart [`bitnami/mongodb`](https://artifacthub.io/packages/helm/bitnami/mongodb) это поддерживает). Для поиска горячих шардов выставим ключи:
  * `metrics.enabled=true`;
  * `metrics.all=true`;
  * `metrics.serviceMonitor.extraFlags="--collect-all"`
* **Не использовать шардирование по категории.** Как вариант -- разбить категорию "Электроника" на подкатегории и делать хеш-шардирование товаров по `category_id, subcategory_id`).

## Недостатки выбранного решения:
- нужно время на реализацию нагрузочных тестов;
- новая стратегия шардирования может дать меньшую общую производительность по записи в коллекцию `Product` (скорее всего, не критично);
- нужно дополнительно устанавливать Prometheus + Grafana;
- Prometheus + Grafana тоже дадут накладные расходы по производительности
- Часть метрик явно будут избыточными (со временем можно отключить).
